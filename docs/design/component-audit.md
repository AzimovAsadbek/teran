# Component audit

Every interactive building block of the storefront and admin: what it was before the redesign,
what it is now, its variants and states, and how it behaves for keyboard and screen-reader users.
Code: `apps/web/src/components`. Tokens: [design system](./design-system.md); type roles:
[typography](./typography.md).

## Principles

- **Native first.** Buttons are `<button>`, links are `<a>`, choices are `<input type="radio">`
  and `<input type="checkbox">`, selects are `<select>`, dialogs are `<dialog>`. Their appearance
  is customised; their keyboard behaviour, form participation and mobile pickers are not replaced.
- **One primitive per job.** Pages compose primitives instead of styling controls by hand.
- **Options, not overrides.** `cn()` joins classes without conflict resolution (no
  `tailwind-merge`), so two classes that set the same property resolve by stylesheet order, not
  by intent. That caused three of the audit's bugs (bag drawer width, gallery arrows hidden
  behind the image, account icon showing on phones). Primitives therefore expose options
  (`size`, `fullWidth`, `variant`, Wordmark `size`) and callers only add classes for properties
  the primitive does not set (margin, width, grid placement). A scan of every rendered page for
  pairs of unprefixed utilities that set the same property now finds none (it found five real
  conflicts during the redesign; all were fixed at the source).
- **Busy is not disabled.** A button that is working shows a spinner, gets `aria-busy` and
  `aria-disabled`, and ignores clicks, but keeps keyboard focus. A `disabled` button drops focus
  to the page, which also broke "focus returns to the opener" for the bag drawer.

## Validation feedback

1. Fields validate on submit (the same Zod schemas as the API), not while typing.
2. On failure: a summary alert above the form, each invalid field marked with `aria-invalid`, an
   error line with an icon under it, and focus moved to the first invalid field.
3. An error disappears as soon as its field changes (checkout); the summary stays until the next
   submit.
4. Server errors map to the same field paths (`VALIDATION_FAILED`) or to a notice next to the
   submit button (price changed, stock changed, bag empty), each with a way forward ("Edit bag").

## Migration status

Counted in `apps/web/src` before (commit `cec1e72`) and after the redesign:

| Measure                                                                                | Before | After |
| -------------------------------------------------------------------------------------- | -----: | ----: |
| Hand-styled forest pill buttons                                                        |     20 |     0 |
| Raw `<button>`/`<input>`/`<select>`/`<textarea>` with their own class lists            |     27 |     5 |
| Radius through arbitrary `rounded-[var(--…)]` classes                                  |     80 |     0 |
| Legacy text colours (`text-ink-*`) instead of semantic tokens                          |    226 |     0 |
| One-off serif sizes (`font-display text-2xl`, …)                                       |     38 |     1 |
| One-off font sizes (`text-[…rem]`)                                                     |     13 |     0 |
| `rounded-full` (now only icon buttons, chips, badges, pills, radios, decorative rings) |     99 |    50 |

The five remaining raw controls are deliberate: the search page's input inside a combined
search field, the two honeypot inputs on forms (hidden), the header's search button drawn as a
search box on wide screens, and the admin's file input (visually hidden inside a styled label).
