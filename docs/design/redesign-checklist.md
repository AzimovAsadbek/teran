# Redesign checklist

Route-by-route record of the redesign: the state before (commit `cec1e72`), the problems found in
the [current design audit](./current-design-audit.md) (finding numbers in brackets), what changed,
and how it was verified. Screenshots of the same states before and after are in
[`screenshots/`](./screenshots/).

**Verification methods** used below:

- **Shots**: before/after captures of the same state on the production build with the same
  seeded data (desktop 1440 × 900, phone 390 × 844, tablet 768 and 1024).
- **Sweep**: every listed route loaded at 360, 390, 768, 1024, 1440 and 1920 px (admin at 390,
  1024 and 1440): no sideways scrolling, no console errors.
- **E2E**: the Playwright journeys (`e2e/tests`), including axe (WCAG 2.0–2.2 A/AA rules).
- **Keys**: scripted keyboard checks (Tab order, Enter, arrow keys, Esc, focus return).
- **Conflicts**: scan of every rendered page for two utilities that set the same property.

| Lighthouse 13.5, desktop                                  | Performance 99–100, accessibility 100, best practices 96–100                                                                                                                                                           |
| Lighthouse 13.5, mobile (simulated throttling)            | Performance 84–91 (before: 85–98), accessibility 100, best practices 100, layout shift 0–0.001                                                                                                                         |
| Lighthouse 13.5, mobile (applied throttling)              | Performance 88–95, largest contentful paint 1.9–2.3 s                                                                                                                                                                  |
| SEO score                                                 | 58–69 by design: demonstration mode marks every page `noindex`                                                                                                                                                         |

Lighthouse pages: `/`, `/ru`, `/en/catalog`, `/en/products/classic-black-tea` on the end-to-end
stack. The simulated mobile score fell most on the home page (98 → 91): the new build streams the
whole static shell at once, so the browser discovers the page's JavaScript before the headline is
painted, and Lighthouse's simulation counts those downloads against the largest contentful paint.
In a real browser with 4× CPU throttling the headline paints at 0.25–0.3 s, unchanged by the
entrance animation or the web fonts.

Not done: screen-reader passes (VoiceOver, NVDA), real iOS and Android devices, and browsers
other than Chromium. These remain on the manual release checklist in the
[test strategy](../testing/test-strategy.md#manual-checks-before-a-release).
